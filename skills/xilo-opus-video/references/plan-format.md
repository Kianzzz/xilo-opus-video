# 三个方案的写法

三个方案一起给，方便用户对比。每个方案控制在一屏以内，用户扫一眼就能判断喜不喜欢。

## 格式

```markdown
### 方案 A：【一个好记的名字】

**一句话**：【这支视频怎么讲、看完留下什么】
**风格**：【画面语言 + 配色（2–4 个色值）+ 字体】
**规格**：【时长】秒 · 【画幅】 · 【帧率】fps
**技术组合**：【比如 HTML/CSS/SVG + 弹簧动画 + 代码合成音效】

**画面概括**
1. 0–3s　【开场画面，一两句话】
2. 3–8s　【……】
3. ……
（镜头数按时长来，每个镜头至少 2–3 秒：15 秒以内 4–5 个，30 秒 6–10 个，更长的按段落分组；写画面里有什么、怎么动、怎么转到下一个镜头）

**声音**：【配乐风格和 BPM / 音效 / 是否配音】
**预计**：渲染约【X】分钟 · 难点【一句话】
**适合**：【为什么这个方案适合这份原材料】

预览：previews/plan-a.png
```

## 三个方案怎么拉开

- **A 稳妥**：最贴近原材料和参考视频，信息最完整。
- **B 换画面语言**：同样的内容换一种风格，比如从扁平换成像素、从深色科技感换成彩铅手绘。
- **C 换讲法**：结构上大胆一点，比如全片一个贯穿的视觉主角、一个不切镜头的长镜头、倒叙、用一个比喻把整件事讲完。

三个方案的技术组合最好不完全一样，这样预览出来差别明显，用户才好选。

## 写画面概括要注意

- 写具体画面，「一个黑色胶囊按钮被光标点击，缩成加载圈」，别写「展示产品功能」。
- 原材料里的事实要对得上，数字、名称、功能不要编。
- 每个镜头只讲一件事；字少而大，每段文字至少停留 2.5 秒。短视频放不下那么多字时，减少镜头或让画面自己讲，不要压缩停留时间。

## 预览

- 默认一张关键帧：挑这个方案里最能代表风格的镜头，只把这一个镜头搭出来（时间从 0 开始算），渲染一张 PNG，画幅用方案的画幅。
- 卖点在运动的方案（变形、卡点、转场）做 2–4 秒小样。
- 预览只是为了看风格，不追求完整，但文字、配色、字体要是真的，不要用占位色块，否则用户没法判断。
- 给用户看之前自己先看一遍预览图。
