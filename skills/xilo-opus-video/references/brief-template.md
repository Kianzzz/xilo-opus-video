# brief.md 模板

用户确认方案后，把确认的内容全部填进来。它既是这次制作的依据，也是一份可以复用的提示词：用户拿去换主题、或者放到别的工具里跑，都能直接用。

填写要求：已经确认的内容写实，不留【】；用户没提、用了默认值的，写明是默认值。

```text
<role>
你是一位动态设计师，也是一位创意程序员，擅长用代码做出有设计感的视频。
</role>

<inputs>
主题：……
想让观众记住的一句话：……
原材料：……（文件路径或链接；参考视频只学结构和手法）
规格：…秒，…×…，…fps
品牌：主色 …，辅色 …，字体 …
声音：配乐 …（BPM …），音效 …，配音 …
</inputs>

<direction>
风格：……
整片只用一套风格、一套配色，同一个角色或元素在每个镜头里的样子都一致。
每个镜头只讲一件事，画面上的字少而大，每段文字至少停留 2.5 秒。
动画用缓动或弹簧，不用匀速运动；转场从画面内容里长出来，不用默认的淡入淡出。
镜头：……（推、拉、跟随，主体在画面里足够大）
禁止：……（按这支片子列具体的，比如居中大字加渐变背景的默认风格、所有元素同时淡入、满屏小字）
</direction>

<structure>
节拍网格 / 旁白时间轴：……
镜头 1｜0.0–3.0s
画面：……
动作：进场 …，主要动作 …，出场 …
镜头：……
声音：……
转场：……
镜头 2｜……
……
</structure>

<build>
1. 画面：……（技术组合），不用外部图片和素材（用户提供的除外）。
2. 页面暴露 window.render(t)，画出第 t 秒；所有画面只由 t 算出来，随机数带固定种子，不用计时器，帧和帧之间不保存状态。
3. 渲染：Playwright 逐帧调用 render(t) 截图，ffmpeg 合成 MP4。（需要运动模糊：每帧 4 个子帧混合）
4. 声音：……；音效放在画面动作发生的那一帧；配音整段合成；混音后响度 -14 LUFS，峰值低于 -1 dBTP。
5. 每做完一个镜头渲 3 张静帧自己检查：文字溢出、元素重叠、主体大小、文字停留时间，修好再做下一个。
</build>

<gotchas>
……（这支片子特有的坑，比如：字体加载完再截图；WebGL 先渲一帧确认生效；绿幕先抠一帧看边缘；循环视频首尾帧完全一致）
</gotchas>

<start>
按镜头顺序制作，每个镜头完成后先出静帧检查；全部完成后渲染整片，出一张抽帧图验收，再交付。
</start>
```
